# v1.5.1：HDA 首次导入优化

## 范围

仅优化 HDA 初次导入执行路径，不修改 DA 时间轴缓存、Parquet 列约定、数据库结构、唯一索引和 v1.5 观测语义。旧 v1.5 runtime 可继续使用；历史版本迁移要求仍以 v1.5.0 文档为准。

## 实现

原路径为每个文件执行冲突检查、去重插入、观测计数三次宽转长展开；随库增长，两个历史关联也不断变重。

新路径在同一文件事务中先查询该文件位号 ID 是否已有历史：

- 没有历史：直接插入一次展开结果，用驱动 RowsAffected 获取实际观测数，不重复展开、关联和计数。
- 已有历史：沿用原冲突检查和相同点去重逻辑，包括混合新旧位号的文件。
- 保留 UNIQUE(tag_id,ts)、时间戳非空和严格递增检查、状态验证及文件哈希校验。
- 位号注册、历史写入、导入完成标记仍在同一个事务；进度和样本数仅在提交成功后增加。

这不是“取消校验”或“删除索引”，也没有对全部 runtime 做强制重建。

## 回归与复测方式

新增 `import_fastpath_test.go` 覆盖首次写入、非空库里的新位号、重叠数据去重、冲突回滚、取消、毫秒精度、零、负数、NULL 跳过与无值 Bad。

`import_benchmark_test.go` 是显式启用的真实文件磁盘测试，默认跳过，不启动服务或 DA。
设置 `HDA_IMPORT_BENCH` 为 preset 目录，`HDA_IMPORT_BENCH_DB` 为不存在的临时数据库路径后，运行：

```powershell
go test -run '^TestImportDatasetBenchmark$' -count=1 -v -timeout 15m
```

耗时只覆盖 `importFilesContext`，不包含文件预检、内容指纹核验、关库或 DA 加载；日志另列关库耗时。
内容核验包含总点数、首末微秒时间及位号名/时间/值/质量的全量聚合指纹；指纹不是逐点比较的数学证明，需结合回归测试使用。
旧版和新版使用相同输入、驱动和测试程序结构，各自从空库导入；基线测试程序在修改导入代码前构建。

## 2026-10-21 本机实测

数据：`presets/oom_test/hda/`，12份文件、300个位号、2026-08-01至2026-10-01 UTC，共59,191,794个有效点。
同一 Windows 机器，Go 1.25、WinLibs GCC 16.1、go-duckdb v1.8.5；每版本一次完整导入，不是多轮统计结果，也没有强制清空操作系统缓存。
基线运行早期有短暂的优化版编译及小规模回归工作并行；不是完全隔离的性能实验，因此改善比例应作为本机观察值，不作精确性能保证。

| 指标 | 原版 v1.5.0 | 新路径 v1.5.1 |
|---|---:|---:|
| 12文件完整导入 | 149.800秒 | 51.392秒 |
| 关库 | 0.338秒 | 0.125秒 |
| 实际/报告点数 | 59,191,794 | 59,191,794 |
| 首时间（epoch微秒） | 1785542400140000 | 1785542400140000 |
| 末时间（epoch微秒） | 1790812799982000 | 1790812799982000 |
| 全量内容聚合指纹 | 684606104330973122 | 684606104330973122 |
| 重试跳过文件 | 12/12 | 12/12 |

本次耗时减少约65.7%，导入速度约2.91倍。首文件由约5.56秒变为3.90秒，末文件由约20.20秒变为4.74秒，避免了随库增长而加重的历史关联开销。
基准不加载DA，不代表完整启动也只需51秒；1天DA的加载耗时及约19.4GiB内存问题未优化。
测试数据库已清理，保留数据源、测试代码、结果记录及旧数据备份；清理的测试数据库可通过重新导入生成。
