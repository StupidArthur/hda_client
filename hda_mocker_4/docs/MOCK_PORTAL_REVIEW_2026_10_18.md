# Mock 门户代码与 UI 评审

评审日期：2026-10-18。对象为当前工作区的 `hda_mocker_4/mock_portal/`，不是仅依据交付报告。只评审，未修复实现代码。

结论：主要功能和技术方向成立，CLI代码/模块依赖未混入门户；但存在会使诊断归属和健康状态失真的问题，建议修复下列P1/P2后再验收。UI整体符合macOS克制风格与三页签要求，仍应收敛无诊断时的展示。

## 必须修复

### R1 / P1：诊断地址变化后，未完成的旧请求仍会污染新地址状态

位置：`mock_portal/internal/diagnostics/manager.go` 的 `ensure`（约192行）、`fetchDiag`（约220行）、`Detail`请求回写（约393行）。

`ensure`会清空缓存，但不会取消或隔离旧请求。网络请求完成后，代码按同一个preset ID重新取当前state，直接写入结果，没有检查请求所属的URL/配置代次。`Detail`还会对已被新地址重置的detailBusy/detailDone状态进行回写。

复现：让旧地址请求阻塞；将同一preset地址切到新地址（甚至新地址端口根本未监听）；放行旧请求。实测新地址变为 `State:ok SourceMessage:OLD-TARGET`；detail也返回旧地址的 `version:OLD-TARGET` 且无错误。

影响：用户刚修改config，网站显示的绿色状态、版本或指标可能仍来自旧Mock，与唯一信息来源的承诺矛盾。并发详情还可能破坏合并请求的状态。

建议：为每次目标配置生成generation/token，网络请求捕获目标及generation；完成时仅回写同一generation。旧请求取消或丢弃结果，in-flight句柄按代次持有，不让旧请求清掉新请求的busy标记。补并发切换地址测试，不能只测试“已有缓存后改地址”。

### R2 / P1：远端Mock的环回诊断配置会被当作门户本机目标探测

位置：`mock_portal/internal/catalog/config.go` 的 `deriveDiagTarget`，约147—151行；前端只在AddressSummary显示警告，未阻止错误采集。

复现：UA为 `opc.tcp://203.0.113.10:4840`，diagnostic.listen为 `127.0.0.1:18990`。代码返回 `State:monitored URL:http://127.0.0.1:18990`，即让门户访问自己的localhost。

影响：跨机使用配置时，本地恰好有同端口HTTP诊断服务就会把另一个进程的状态当成远端Mock，不能仅靠“仅本机”的UI提示解决。设计文档第5.2节已明确禁止这种误连。

建议：结合本机接口地址检查UA目标是否为本机；不能确认同机时，环回诊断地址显示配置不可用/无法从本机访问，不探测。不新增第二套逐实例地址登记。覆盖IPv4/IPv6环回、localhost、真实本机网卡IP与远端IP组合。

### R3 / P2：目录读取失败的过期标记会被两秒缓存分支抹掉

位置：`mock_portal/internal/catalog/catalog.go` 约131—142行。

失败路径更新lastScan、返回stale副本，但未将错误状态存回缓存。两秒内下一次Snapshot(false)直接返回原c.snapshot，此时Stale=false且Error为空。

复现：成功扫描一份preset；移走测试根目录；强制扫描得到 `stale=true,error=...`；紧接着普通扫描得到 `stale=false,error=""`，虽根目录仍不可读。

影响：多用户或快速刷新时，错误会间歇消失，旧清单被包装成当前正常数据。

建议：将最后一次扫描结果/错误也缓存，或分离“最后成功清单”和“最近扫描状态”；读取恢复前不能返回未过期状态。增加“失败之后紧接着命中缓存”回归用例。

### R4 / P2：详情首次加载失败时永远只显示骨架，不显示错误

位置：`mock_portal/frontend/src/pages/mock-detail.tsx` 约570—612行。

请求失败后setError，但detail仍为null；`if (!detail) return <Skeleton...>`在错误提示之前返回。只有404被单独处理，500/网络中断等没有首屏错误态。

已在浏览器复现：测试HTTP层让 `/api/mocks/basf_dirty` 返回500，列表接口仍正常，直接进入详情。页面持续显示骨架，无“加载失败”、重试或返回操作；并非后台仍在加载。

建议：分离loading和error；首次失败展示错误和重试/返回入口。有旧快照时再保留旧数据并明确过期。测试首次500、网络失败、失败后恢复三种状态。

## UI 评审

### 符合预期

- 左侧仅Mock列表、标准化指南；5份可用preset对应5个条目，demo未计入。
- 详情只有诊断、说明、下载，默认诊断；连接地址放顶部。
- 浅灰侧栏、蓝色选中态、小圆角、系统字体与轻量控件，总体是预期的macOS系统工具风格。
- 说明页成功渲染真实summary.md及GFM位号表；下载按HDA/DA/配置/说明分组，不增加分析功能。
- 通配地址禁用复制，未监控/配置待完善不冒充健康；未知不填0。
- 实测430px宽度，说明页未发生页面级横向溢出；本次正常页面操作未捕获浏览器控制台错误。

### 建议调整

1. **未监控/无快照时收起无意义字段。** 目前BASF无diagnostic.listen，页面仍展开源端状态、历史窗口、最近处理、连接订阅等大量“未知/—”，形成很长的空诊断页。默认只展示原因、配置和少量采集信息；有成功快照再展开具体指标，或用一个“更多诊断字段”折叠区。
2. **详情页保持Mock列表导航高亮。** Shell的根NavLink使用end，进入 `/mocks/:id` 后左侧两个入口都不高亮。详情仍属于Mock列表这一导航分区。
3. **增加小字号与弱色文字的可读性。** 很多主页面地址、状态和解释为11—12px灰字；保留紧凑风格，但主内容可适当提升到13—14px，把11px留给次要时间和辅助提示。
4. **列表HDA 1 / DA 1应注明是文件数。** 当前容易被理解为位号数或点数，尤其QA显示HDA 12 / DA 0。可以直接写“HDA 1文件 · DA 1文件”，无需新增数据来源。

这些UI建议不要求重做设计系统，不应引入更重组件库或数据分析功能。
