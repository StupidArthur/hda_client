# hda_mocker_4 实现设计

状态：已实现（v1.2.1）。本文保留核心服务的设计依据；Windows GUI 的设计与使用见 `HDA_MOCKER_4_MANUAL.md`。

## 1. 目标与边界

新建仓库根目录下的 `hda_mocker_4/`，独立 Go 模块。不修改客户端、mocker_2、mocker_3，不兼容它们的配置。

实现一条完整链路：

```text
原始文件 → Python 预处理 → 标准 HDA Parquet → Go 导入 ─┐
                         标准 DA Parquet → Go 轮播 ──┼→ DuckDB → HDA 查询
                                                    └→ 提交后更新当前值与订阅
```

- Go：配置、文件校验、历史导入、轮播、数据库维护、UA 服务。
- Python：按数据来源编写预处理脚本，只输出标准文件，不访问运行数据库。
- DuckDB：唯一历史查询来源，保存历史、导入记录、播放进度。
- 正常运行无需 Python，无独立数据库服务。everything is file：配置、输入、运行数据都在 preset 内。
- 提供数值型位号、实时 Read/Subscribe、原始 HistoryRead 和本地 Windows GUI。暂不做聚合历史、历史修改、热加载、认证证书组态、数据库插件框架、自动分层归档。
- 不承诺 DuckDB 的写入与分页性能；以本文的实测验收为准。

## 2. 工程与文件约定

```text
hda_mocker_4/
  go.mod
  main.go
  config.go
  dataset.go          # 标准输入校验与位号发现
  store.go            # DuckDB 导入、批写、查询、清理
  playback.go
  server.go           # UA 节点、Read、订阅
  history.go          # HistoryRead、continuation point
  README.md
  presets/demo/
    config.yaml
    prepare.py        # 可选，每个 preset 自己适配来源
    raw/              # 原始文件，Go 不扫描
    hda/              # 带时间的标准 Parquet
    da/               # 无时间的标准 Parquet
    runtime/          # 自动创建，不提交 Git
      history.duckdb  # DuckDB 自身 WAL 等伴随文件也留在此目录
```

保持几个直接协作的模块即可，不再增加接口工厂、插件注册、事件总线、独立任务服务。

路径均相对于所选 config.yaml 的目录。`hda/`、`da/`、`runtime/` 固定，不提供路径配置。只扫描第一层 `*.parquet`，按文件名排序；不扫描 raw 或 runtime。允许只有 HDA 或只有 DA，不允许两者均无有效数据。临时文件使用其他后缀，完成后重命名为 `.parquet`。

```yaml
server:
  endpoint: opc.tcp://0.0.0.0:4840
  ns: 3
  namespace: urn:hda:mocker4
  max_page_size: 5000
playback:
  files:
    hda_all.parquet:
      period_ms: 30000
    dynamic_data_all.parquet:
      period_ms: 60000
history:
  retention_days: 0
```

启动示例：`hda_mocker_4.exe --config presets/demo/config.yaml`。
`ns` 是实际 NodeId 使用的 namespace index，`namespace` 是对应的 namespace URI，两者均由配置确定。每份 DA Parquet 必须按精确文件名单独配置周期，周期和页上限必须大于零；缺少文件配置或配置了不存在的文件均报错。保留天数为非负整数，0 为不删除。未知配置字段报错。

## 3. Python 与 Go 的数据契约

采用宽表，列名就是位号名。标准 HDA 第一列固定为 `Timestamp`，类型为 `timestamp[us, tz=UTC]`；其余列为 float64。标准 DA 仅有 float64 位号列，没有时间列。两者至少一行、一个位号。

HDA 时间必须非空、严格递增，不要求等间隔。标准化到微秒导致时间重复时预处理报错。DA 按文件行顺序播放。位号名非空且唯一，`Timestamp` 为保留名。

第一版质量规则：有限数值为 Good；Null、NaN、正负 Inf 转为 UA 空值与 BadNoData，样本仍入历史，不跳过。有限数值原样保留，不根据负值或零推断异常。暂不支持独立质量列与其他 UA 数据类型。

同一目录中的多个文件不允许位号重名；HDA 与 DA 之间允许同名，合为一个 UA 节点。保留不同目录重名能力是为了旧历史与实时采集使用同一批位号。

Python 预处理要求：

- 来源适配直接写在 preset 的 prepare.py 中，不设计通用转换 DSL。
- 原始无时区时间必须由脚本明确指定来源时区再转 UTC，不猜测。
- 输出固定契约，校验失败不得覆盖已有有效输出。
- 已符合契约的文件可直接放入 hda/ 或 da/。
- 示例使用 external 中的“HDA 完整集”与“da 轮播子集”：前者转换时间类型和时区，后者移除 Timestamp。
- 上述完整集实测 452,161 行、76 位号；子集 10,000 行、同样 76 位号，等于完整集前 10,000 行。原始文件无时区，示例脚本必须要求明确提供来源时区。

## 4. 存储模型

Go 进程独占数据库管理权。集中一个写入执行路径；查询使用独立连接。DuckDB 驱动选择维护中的 Go 绑定，锁定版本。先验证 Windows 构建、原生依赖、持久化与事务，再开发完整功能；在 README 写清构建和随程序分发的依赖，不能假定 CGO_ENABLED=0 或一定只有一个 exe。

逻辑表如下，字段可按驱动实际类型映射，但不能改变含义：

| 表 | 必要字段及含义 |
|---|---|
| tags | 稳定 tag_id、唯一 name |
| imports | HDA 相对文件名、SHA-256、行数、完成状态 |
| samples | tag_id、ts（UTC Unix epoch 微秒 BIGINT）、value（可空 DOUBLE）、quality（uint32）、origin（import/live）、batch_id |
| playback_state | DA 相对文件名、SHA-256、next_row |
| state | 数据格式版本、最后已提交 batch_id、最后轮播时间 |

样本在逻辑上以 `(tag_id, ts)` 唯一。导入批次为 0，实时批次单调递增。import/live 来源用于保留策略，不对外变成两套历史。

初始物理实现用统一长表，历史导入按位号、时间组织数据。库内时间保存为 UTC Unix epoch 微秒整数，避免 DuckDB `TIMESTAMPTZ` 自动加载 ICU 扩展；Go/UA 边界恢复为 UTC `time.Time`。不要为了索引预先复制两套样本表；依据真实查询计划和验收结果再调存储排序或必要索引。宽转长必须保留空值行，不能使用默认丢弃 Null 的转换行为。

优先通过 DuckDB 的 Parquet 读取能力批量导入，动态列名必须正确引用，文件路径和值使用参数绑定。不得把完整集展开成数千万个 Go 对象。实时写入用批量方式或 Appender，明确 flush 和事务边界，不能一位号一事务。

## 5. 启动、导入与重启

顺序：读取配置 → 校验输入 → 打开库并检查版本 → 导入新 HDA → 注册所有库内位号和 DA 位号 → 恢复当前值/进度 → 开放 UA 并开始轮播。

- SHA-256 相同的 HDA 内容跳过，重复启动不得重复导入；同一批输入中位号重复仍报错。
- 每个文件的样本与完成记录在同一事务中提交。失败回滚该文件；错误明确指出文件与原因，UA 尚未开放。之前成功的文件不需重导。
- 已导入路径的内容变了，启动报错，第一版不做原位替换或自动覆盖。
- 增量导入遇到同位号同时间：内容相同跳过，内容不同报错回滚。原样保留已有记录，不静默覆盖。
- 移走 HDA 文件不删除已导入数据；数据库中的位号继续存在。
- DA 文件内容变化时该文件进度重置到第一行，旧历史保留并记录日志。相同内容恢复 next_row；移走 DA 文件停止该文件轮播，已存历史保留。
- 运行数据库版本不兼容明确报错，不自动删除重建。
- 首版重新导入/从头开始的方法是停服、备份并移走整个 runtime，再启动；这会重建运行历史，README 必须明确说明。

## 6. 轮播与一致性

每份 DA 文件使用自己的配置周期并维护独立进度，各自到尾回到零。第一轮在启动就绪后立即执行；之后同一时刻到期的文件合并为一批，共享一个实际 UTC 时间戳。

一次轮播流程：取当前行 → 生成时间和 batch_id → 事务写所有样本及所有 next_row → 提交 → 原子替换内存当前值 → 通知 UA 监控项。

- 写入失败不前进、不发布新值，停止轮播并报错；禁止无界内存积压。
- 提交后、发布前进程崩溃，重启从数据库恢复当前值和下一行。历史不会丢失，离线订阅通知不补发，不承诺通知恰好一次。
- 相同数值也记录历史；通知是否发送由 UA 监控过滤条件决定，不能把每轮必落库误实现为每轮必通知。
- 停机时间不补造数据，运行延迟也不密集补发。处理超周期记录日志并延后下一轮。
- 新轮播时间必须大于上次已提交轮播时间；时钟回退时暂停并报错，不伪造未来时间。
- 同名 HDA 的最后时间必须早于该位号首个实时样本时间；否则暂停启动轮播并报错，不覆盖未来历史。
- HDA-only 当前值取最新历史样本；DA-only 尚未产生样本时返回 BadWaitingForInitialData。
- 每次事务按一轮提交，先保证可见性一致。若实测小周期提交成为瓶颈，再单独讨论批次延迟，不能偷偷改变此规则。

## 7. UA 与分页

参考 mocker_3 的 gopcua 服务接入与 HistoryRead handler，复用经过确认的协议代码；不要复制旧合成数据、时间切片或重算当前时间的分页逻辑。

- namespace URI 来自配置，NodeId 使用注册的 namespace 索引和字符串位号名。不要假定索引永远为 2。
- 实现 Browse、Read、真实 CreateSubscription/MonitoredItems/Publish 数据变化通知；更新内存值不等于实现订阅。
- HistoryRead 支持原始值正向/反向读取；标准支持范围和未实现参数须在 README 列明。不支持的 modified、bounds、聚合等请求返回对应 UA 不支持状态，不静默忽略。时间端点及缺省时间语义按 OPC UA ReadRawModifiedDetails 实现，编码前核对官方规范。
- 客户端每节点数量 > 0 时，页大小取它与 server.max_page_size 的较小值；为 0 时使用服务端上限，不等于无限返回。
- 一次请求可含多个位号，每个位号有独立分页状态。
- continuation point 是不透明随机 token，绑定 session、位号、首请求参数、方向、最后返回时间和首请求已提交 batch_id。
- 后续页按游标查询，不用 OFFSET，不重新计算查询时间范围；只读 batch_id 不超过首请求上界的数据，实时新增不会混进旧查询。
- token 可以保持相同而内部游标前进；首版采用此方式，覆盖曾出现的客户端兼容问题。没有剩余数据不返回 token，不能靠 token 字节变化表示进度。
- 显式释放、session 关闭、空闲 5 分钟均清理 token。非法或跨 session token 返回 BadContinuationPointInvalid。设置固定资源上限并使用对应 UA 状态拒绝超量分配，不无限缓存。
- 不为分页常驻一份完整查询结果，也不长期持有 DuckDB 读事务。由不可修改样本、batch 上界、游标以及清理保护共同保持查询稳定。

## 8. 历史维护

retention_days 只作用于 live 数据，以当前 UTC 时间计算截止点；import 数据保留。每小时由统一写入路径执行一次清理，与轮播串行安排，记录耗时。

有活动分页时暂缓清理，避免后续页缺失；token 空闲超时后释放保护。第一版接受持续活跃查询导致清理延期，不为此实现复杂 MVCC 副本。

删除记录不承诺数据库文件立即缩小。验收记录删除后的文件体积和空间复用情况，不附加自动 VACUUM/重建流程。停服后备份整个 preset；不得运行中只复制主数据库文件而忽略伴随文件。

## 9. 实现顺序

1. 打通 Go + DuckDB 在目标 Windows 环境的构建、批写、事务、重启读取；选定并锁定驱动版本。
2. 完成配置、标准文件校验、示例 prepare.py、幂等导入。
3. 完成轮播、持久化进度、当前值恢复。
4. 接入 UA Read/Subscribe/HistoryRead，完成分页生命周期。
5. 加入保留策略、必要日志、README，执行下述验收并记录结果。

日志至少包含导入进度/耗时/样本数、已注册位号数、轮播提交耗时和落后情况、数据库错误、清理结果。不要逐点打印正常数据。

## 10. 最小验收

用小数据验证正确性，用完整集验证规模。不要为了覆盖率大量增加重复测试。

| 场景 | 必须观察到的结果 |
|---|---|
| 输入契约 | 无时区标准时间、重复位号、重复时间、错误类型明确失败；Null 样本保留为 Bad |
| 首次导入/重启 | 完整集导入 34,364,236 样本；重启数量不增长；随机位号时间和值与源一致 |
| 轮播/恢复 | 2～3 行小 DA 连续绕回；时间为运行时间；重启从已提交下一行继续 |
| 写入故障 | 提交失败不改变进度、不发布新实时值；提交后重启恢复一致 |
| 实际订阅 | 用真实 UA 客户端订阅，收到变化；同时间值能在 HDA 查到，不只验证主动 Read |
| 分页 | 分别测试客户端小于/大于服务端上限、0、正反向、多位号、稳定 token、释放与跨 session；无丢点、无重复点 |
| 查询期间写入/清理 | 翻页结果不混入新批次；清理不删除活动分页所需数据 |
| 长期维护 | live 过期记录被清理，import 保留；重启和进度不受清理影响 |

性能报告使用现有完整集与 76 位号 DA，分别测试 1000 ms、100 ms 周期。比较无轮播和轮播同时查询，固定同一客户端、并发数、页大小、时间范围、UA 连接数；记录实际参数。

报告初始导入时间、库体积、峰值内存、写入提交耗时与落后次数、HDA 实际样本吞吐及 CPU。需要评估更大历史时可离线平移时间生成明确标注的扩展测试数据，不能用几分钟运行代表全年性能。没有实测就不写提升倍数；发现瓶颈先报告证据，再做局部优化。

交付包括源码、依赖锁定、可运行 preset 和预处理脚本、Windows 构建/运行说明、验收报告。此设计不授权提交推送或覆盖用户现有数据。
